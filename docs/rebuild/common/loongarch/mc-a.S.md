# `common/loongarch/mc-a.S` — LoongArch LSX/LASX motion-compensation assembly

**Dirty-side behavioural specification.** Source path: `E:\_x264_dirty_stash\x264-source\common\loongarch\mc-a.S`. Role: assembly implementations of chroma interpolation, block averaging (plain and weighted), weighted prediction (normal and no-denominator), block copy, zeroing, half-pel filter generation, low-resolution frame generation, plane interleave/deinterleave, and prefetch hints.

## 1. Header

The title line above gives the source path and the file's role in one sentence; the adjacent bold marker identifies this document as a **dirty-side behavioural specification** written from the reference source and public literature. No reference source or near-verbatim pseudocode is reproduced.

## 2. Purpose

This is the LoongArch equivalent of `mips/mc-c.c`'s kernels, split into LSX (128-bit) and LASX (256-bit) variants. It covers the same bandwidth-critical paths — sample interpolation, averaging and weighted prediction — plus plane-format helpers. The C file `mc-c.c` wires these symbols into the function tables.

## 3. Public interface

Exports (prefixed by `ASM_REF`), declared in `loongarch/mc.h.md`:

**Chroma interpolation:** `mc_chroma_lsx`, `mc_chroma_lasx`.

**Averaging:** `pixel_avg_weight_w4/w8/w16_lsx/_lasx`, `pixel_avg_w4/w8/w16_lsx/_lasx`, plus macro-generated `pixel_avg_WxH_lsx/lasx` for all nine block sizes and width helpers `pixel_avg2_w4/w8/w16/w20_lsx/_lasx`.

**Weighted prediction:** `mc_weight_w20/w16/w8/w4_noden_lsx/_lasx` and `mc_weight_w20/w16/w8/w4_lsx/_lasx`.

**Copy/memory:** `mc_copy_w16/w8/w4_lsx/_lasx`, `memzero_aligned_lsx/_lasx`, (LSX) `memcpy_aligned_lsx`.

**Filtering/frame:** `hpel_filter_lsx/_lasx`, `frame_init_lowres_core_lsx/_lasx`.

**Plane helpers:** `store_interleave_chroma_lsx`, `load_deinterleave_chroma_fenc_lsx`, `load_deinterleave_chroma_fdec_lsx`, `plane_copy_interleave_core_lsx/_lasx`, `plane_copy_deinterleave_lsx/_lasx`, `plane_copy_deinterleave_yuyv_lsx/_lasx` (macro-generated).

**Prefetch:** `prefetch_ref_lsx`, `prefetch_fenc_420_lsx`, `prefetch_fenc_422_lsx`.

## 4. State and data structures

No globals. Constants and shuffle tables are local `const` objects defined in `loongson_asm.S`/`pixel-a.S` or as immediate masks in instructions. Working data lives in `vr*`/`xr*` registers. Row loops are generally unrolled by four; tails are handled scalar-wise by the C dispatchers (`mc-c.c`) or by scalar loops within the assembly.

## 5. Algorithm / behaviour

### Chroma interpolation (`mc_chroma_*`)

Takes separate U/V destinations and an interleaved source. Computes `dx = mvx & 7`, `dy = mvy & 7`, with horizontal weights `(8−dx, dx)` and vertical weights `(8−dy, dy)`, offsets the source by `(mvy>>3)*stride + (mvx>>3)*2`. Uses byte shuffles to gather adjacent chroma pairs from the interleaved stream, unsigned dot products with the horizontal weights, then multiplies by the vertical weights, rounds right by **6** and saturates to 8-bit. Results are stored as 16-bit pairs into the separate U and V planes. LASX processes 8 or more chroma samples per vector.

### Block averaging

- **Plain (`pixel_avg_w*`):** `dst[i] = (src0[i] + src1[i] + 1) >> 1` per byte, unrolled over four rows per vector sequence.
- **Weighted (`pixel_avg_weight_w*`):** `dst = (w·src0 + (64−w)·src1 + rounding) >> 6`, clipped to `[0,255]`. The weight and its complement are broadcast into vector lanes; dot-product helpers accumulate both sources in one pass.
- **WxH variants (`pixel_avg_\w x \h_*`):** generated by a macro that calls the width helper with the specific height and weight; they cover 16x16, 16x8, 8x16, 8x8, 8x4, 4x16, 4x8, 4x4, 4x2.
- **Width helpers (`pixel_avg2_w*`):** used by `mc_luma`/`get_ref` for fractional-pel averaging; slot 20 is `w16 + w4`, slot 12 is not installed.

### Weighted prediction

Two families:

- `_lasx/_lsx` (normal): reads `weight->i_scale`, `i_offset`, `i_denom`; computes `offset' = (offset << denom) + (denom ? 1<<(denom−1) : 0)`, widens source bytes, multiplies by scale, adds offset with saturation, clamps to ≥0, shifts right logically by `denom`, saturates to 8-bit.
- `_noden_*`: used when `i_denom == 0`; omits the shift and uses rounding appropriate for the no-denominator formula.

Widths 4/8/16/20 are handled; height is passed per call.

### Copy and zeroing

`mc_copy_w4/w8/w16_*` copy `height` rows of 4/8/16 bytes from source stride to destination stride using full-width vector loads/stores, unrolled in groups of four rows. `memzero_aligned_*` writes zero vectors over a byte count supplied in `$a1`, with a scalar tail.

### Half-pel filter (`hpel_filter_*`)

Generates three filtered planes from a full-pel luma plane: horizontal-only, vertical-only and the 6x6 center. Applies the H.264 6-tap `[1,−5,20,20,−5,1]` filter in x and/or y, with `(sum + 32) >> 6` scaling and signed saturation to 7 bits where required, then converts back to unsigned bytes. Processes the width in groups of 16 (LSX) or 32 (LASX) bytes.

### Low-resolution frame (`frame_init_lowres_core_*`)

Produces four half-size planes from a full-size luma plane by averaging 2x2 neighborhoods: load three consecutive source rows, form even/odd byte groups with `pckev`/`pckod` (or `vilvl`/`vilvh`), average with `aver_u_b`, and store to four destinations in raster order. Handles widths in 16/32-byte chunks plus tails.

### Plane helpers

- `store_interleave_chroma_lsx`: merges U and V planes into interleaved chroma, four rows at a time, using `ilvr_b`/`ilvl_b`.
- `load_deinterleave_chroma_fenc/fdec_lsx`: split interleaved chroma into FENC/FDEC-stride planes using `pckev`/`pckod`.
- `plane_copy_interleave_core_*`, `plane_copy_deinterleave_*`, `plane_copy_deinterleave_yuyv_*`: generic planar↔interleaved and YUYV↔planar conversions with vector loops and scalar tails, generated by macros defined in generic headers.

### Prefetch

`prefetch_fenc_420/422_lsx` and `prefetch_ref_lsx` issue LoongArch prefetch instructions for future macroblock rows; they have no observable output and exist purely as performance hints.

## 6. Dependencies

- **Calls:** macros from `loongson_asm.S` (dot-product, clip, transpose, strided loads) and `loongson_util.S` (function macros, `FENC_STRIDE`, `FDEC_STRIDE`).
- **Called by:** `mc-c.c` dispatcher and through `x264_mc_functions_t` from `common/mc.c`.
- **Shared config:** `HIGH_BIT_DEPTH == 0`, `BIT_DEPTH`, CPU flags.

## 7. Constants and tables

- 6-tap filter coefficients `[1,−5,20,20,−5,1]` and shift `>>6` with rounding constant 32.
- Luma weights `(w, 64−w)` with denominator 5; clip bound 255.
- Chroma shift `>>6`.
- Plane interleave/deinterleave masks (e.g. `{0,3,6,9,12,15,18,21}` style for RGB/YUYV in related kernels).
- Row unroll factor 4; vector widths 16 (LSX) / 32 (LASX) bytes.

## 8. Performance notes

- **Hotness:** highest for inter frames; every macroblock calls averaging/copy/filter paths.
- **SIMD status:** fully LSX/LASX except prefetch (hints) and scalar tails.
- **Optimization tips:** (a) keep the weighted-predicate check out of inner loops (the C dispatcher already selects the variant); (b) use LASX variants whenever available — they halve the number of loop iterations; (c) align source/destination pointers to 32 bytes for LASX; (d) the half-pel filter is the main cost — reuse the generated planes across all candidate motion vectors (the encoder already does); (e) prefetch hints should target the next macroblock row, not the current one.

## 10. Verification checklist

1. For all qpel positions, compare `mc_chroma_*` with the scalar reference for widths 2/4/8 and heights 2/4/8/16.
2. Plain and weighted averages: test weight 0, 32, 63 and out-of-range values; check rounding and clipping at 0/255.
3. Weighted prediction: verify normal vs no-denominator table selection via `weight_cache` in `mc-c.c`.
4. Copy/zero: verify strided behavior and exact byte counts including tails.
5. `hpel_filter_*`: compare the three output planes against scalar filter output for random input.
6. `frame_init_lowres_core_*`: compare four downsampled planes with scalar 2x2 averages.
7. Plane interleave/deinterleave and YUYV round-trip with random data.
8. Verify LSX and LASX variants produce identical results.
9. Prefetch functions should have no observable side effects on output buffers.
