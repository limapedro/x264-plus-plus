# `common/opencl/intra.cl`

**Role:** Computes, per half-resolution macroblock, the lowest SATD cost among ten H.264 intra prediction modes and reduces those costs into per-row and per-frame statistics for lookahead frame-type decisions.

> **Dirty-side behavioural specification.** Describes observable behaviour and structure only; no source text or near-verbatim pseudocode is reproduced.

---

## 1. Header

- Source path: `common/opencl/intra.cl`
- Role: GPU implementation of the C lookahead's lowres intra analysis — ten directional/DC/planar prediction modes scored with SATD — plus the row-sum reduction that feeds rate control.
- Marker: this document is a dirty-side behavioural specification derived from the reference implementation, public H.264 literature and the referenced source's own design notes.

---

## 2. Purpose

Lookahead needs an intra cost for every lowres macroblock in order to decide whether a frame is better coded as I/P/B and to estimate AQ-weighted complexity. Evaluating ten prediction directions independently per macroblock on a CPU is expensive; this kernel parallelizes across macroblocks, prediction modes and pixel columns simultaneously.

The file is deliberately duplicated: every prediction routine exists in a vectorized form (using `int8`/`int2` operations and swizzles) for older AMD GPUs with wide registers, and in a scalar form (private `pixel[32]` prediction buffers and `uchar8` stores) for NVIDIA and AMD Southern Islands / GCN devices with single-width registers. The host sets `-DVECTORIZE=1` at program build time for the former and leaves it unset for the latter. The source states both variants produce exactly the same SATD results as the C versions in `pixel.c`.

---

## 3. Public interface

Device functions (all internal to the program, not directly enqueueable):

- `satd_8x4_intra_lr(...)` (vectorized) — SATD of an 8×4 residual block against four supplied `int8` prediction rows; loads eight pixels per row from local memory, computes `data - prediction`, swizzles the result into four `int2` pairs, transforms, accumulates absolute values, and returns `(low+high)>>1`.
- `satd_8x4_lp(...)` (scalar variant, generated by the `SATD_C_8x4_Q` macro in `x264-cl.h`) — same mathematical operation with a private prediction buffer and explicit strides.
- `x264_predict_8x8c_h`, `x264_predict_8x8c_v`, `x264_predict_8x8c_dc`, `x264_predict_8x8c_p` — the four chroma-style 8×8 modes: horizontal, vertical, DC with quadrant-specific averages, and planar (gradient-based) prediction.
- `x264_predict_8x8_ddr`, `x264_predict_8x8_vr`, `x264_predict_8x8_hd`, `x264_predict_8x8_hu`, `x264_predict_8x8_ddl`, `x264_predict_8x8_vl` — the six luma directional modes: down-diagonal-right, vertical-right, horizontal-down, horizontal-up, down-diagonal-left and vertical-left.
- Two small packing helpers used only by the scalar path: `pack8to16` (combine two bytes into a 16-bit word) and `pack16to32` (combine two 16-bit words into a 32-bit word).

Kernels:

- **`mb_intra_cost_satd_8x8( read_only image2d_t fenc, global uint16_t *fenc_intra_cost, global int *frame_stats, int lambda, int mb_width, int slow )`** — local dimensions `[32,8]`; global dimensions `[paddedWidth, mb_height]` where `paddedWidth` is `mb_width` rounded up to a multiple of 32.
- **`sum_intra_cost( const global uint16_t *fenc_intra_cost, const global uint16_t *inv_qscale_factor, global int *fenc_row_satds, global int *frame_stats, int mb_width )`** — global `[256, mb_height]`, local `[256,1]`.

## 4. State and data structures

### 4.1 Local memory in `mb_intra_cost_satd_8x8`

- `cache[2385]` — a staging area of 33 macroblock rows (9 sample rows × 265 columns including a one-column left gutter). `CACHE_STRIDE` is 265 and `BLOCK_OFFSET` is 266; macroblock `lx` starts at column `BLOCK_OFFSET + 8*lx`, so column 0 holds the left edge sample and column 265 is unused padding.
- `top[32*16]` — 16 smoothed top samples for each of the 32 macroblocks in the group.
- `left[32*8]` — eight smoothed left samples per macroblock.
- `left_top[32]` — one corner sample per macroblock.
- `cost_buf[32]` — one running minimum cost per macroblock, initialized to `COST_MAX`.

The 33rd macroblock and the extra top row exist so that 32 macroblocks plus their above/left neighbours can be loaded with a single coalesced pattern and padded by edge replication.

### 4.2 Output buffers

- `fenc_intra_cost` — one `uint16_t` per macroblock, indexed `gidy*mb_width + gx`; stores `min_best_satd + 5*lambda`.
- `frame_stats` — four-element `int` buffer; indices 0 (`COST_EST`), 1 (`COST_EST_AQ`) are accumulated by `sum_intra_cost`; index 2 (`INTRA_MBS`) is only accumulated by `sum_inter_cost`, though it is zeroed here.
- `inv_qscale_factor` — per-macroblock 16-bit multiplier, nominally 256; `sum_intra_cost` computes `cost_aq = (cost * inv_qscale_factor + 128) >> 8`.
- `fenc_row_satds` — one `int` per macroblock row; written by thread 0 of each row-group.

## 5. Algorithm / behaviour

### 5.1 Prediction filters and constants

Two filters are used throughout:

- `F1 = rhadd(a,b)` — round-up-half average `(a+b+1)>>1`.
- `F2(a,b,c) = (a + 2*b + c + 2) >> 2` — a symmetric three-tap filter with center weight two and a rounding bias of two, equivalent to rounding `(a+2b+c)/4` to nearest with ties up.

The prediction modes follow H.264 Intra_8×8 / chroma conventions:

- **Horizontal:** every sample in a row equals the sample to the left of that row. The vectorized form broadcasts `src[-1]` into an `int8` per row.
- **Vertical:** every sample in a column equals the sample above it in the row above the block.
- **DC:** four quadrant constants are formed. The upper-left quadrant uses `(top_left_sum + left_top_sum + 4) >> 3`, the upper-right uses `(top_right_sum + 2) >> 2`, the lower-left uses `(left_bottom_sum + 2) >> 2`, and the lower-right uses `(bottom sums + 4) >> 3`. The sums each cover four samples.
- **Planar (P):** compute horizontal gradient `H` and vertical gradient `V` as weighted sums `(i+1)*(right_edge[i] - left_edge[i])` and `(i+1)*(bottom_edge[i] - top_edge[i])` over `i=0..3`; set `a = 16*(bottom-left corner + top-right corner)`, `b = (17*H+16)>>5`, `c = (17*V+16)>>5`, and `i00 = a - 3*b - 3*c + 16`. Each pixel is `clip((i00 + x*b + y*c) >> 5)`, with `b` added per column and `c` per row.
- **Directional modes DDL/DDR/VR/HD/HU/VL:** generate the standard H.264 prediction patterns by sampling the top row, the left column and the top-left corner with `F1`/`F2` according to each direction's extrapolation rule. Edge samples are clamped to the nearest available neighbor; e.g. the DDL mode clamps the diagonal index to `[0,13]` and uses `3*top[15]` for the final corner. The vectorized forms compute an entire prediction row as eight simultaneously evaluated `F2`/`F1` expressions using `int8` swizzles; the scalar forms fill a private 32-byte prediction buffer first.

Every prediction is scored by feeding the predicted rows and the actual block rows into the 8×4 SATD helper; the two 4-row halves are scored separately and added. The SATD routine returns the sum of absolute Hadamard coefficients divided by two.

### 5.2 `mb_intra_cost_satd_8x8` data flow

1. **Work-item identity.** `lx = local_id(0)` in `0..31`, `ly = local_id(1)` in `0..7`, `gx/gy` global counterparts, `gidx = group_id(0)`, `gidy = group_id(1)`. `linear_id = ly*32 + lx`. `basex = gidx<<8` (256 texel columns) and `basey = (gidy<<3)-1` (one row above the group's eight macroblock rows).
2. **Cache load.** Work items with `linear_id < 66` each fetch one `uint4` from `fenc` at `(linear_id<<2 + basex, y + basey)` for `y=0..8` and scatter its four channels into four consecutive cache columns `1+x .. 4+x`. This loads 33 macroblock widths (264 pixels) plus the left gutter. Work items with `linear_id < 9` additionally load the left-edge column at `basex - 1` for rows `basey .. basey+8`. A local barrier follows.
3. **Smoothed edges.** Each work item `(lx,ly)` builds two top samples at `top[lx*16 + ly]` and `top[lx*16 + ly + 8]` with the `[1,2,1]/4` filter over the row above the block, clamping indices to the available 16 samples. It builds one left sample `left[lx*8 + ly]` with the same filter over the left gutter, clamping the below-neighbor index to rows 0..7. Work items with `ly==0` build `left_top[lx]` from the corner neighborhood and initialize `cost_buf[lx] = COST_MAX`. Another barrier follows.
4. **Mode evaluation.** The eight `ly` values select eight different modes with no branch divergence within a warp/wavefront: `ly=0..3` evaluate chroma-style H/V/DC/P on the block at `cache[BLOCK_OFFSET + 8*lx]` with stride 265; `ly=4..7` evaluate luma DDR/VR/HD/HU using the smoothed `top`, `left` and `left_top` arrays. Each result is combined into `cost_buf[lx]` with an atomic local minimum.
5. **Slow modes.** When `slow != 0`, `ly=0` additionally evaluates DDL and `ly=1` evaluates VL, each folded into the same `cost_buf[lx]` with another atomic minimum. The host sets `slow = (i_subpel_refine > 7)`, i.e. presets slow/slower/placebo.
6. **Writeback.** After a barrier, work items with `ly==0` and `gx < mb_width` write `fenc_intra_cost[gidy*mb_width + gx] = cost_buf[lx] + 5*lambda`. Work items with `gx < 2` and `gy==0` zero `frame_stats[0..1]` (and index 2 via `gx<2`? the source writes `frame_stats[gx]` for `gx<2`, so only indices 0 and 1 are initialized here — see Open questions).

### 5.3 `sum_intra_cost`

Each work row `y` is handled by a group of 256 threads in the X dimension. Threads stride across macroblocks (`x += 256`), accumulating four quantities:

- `row_satds` — sum of all AQ-adjusted costs in the row.
- `cost_est` and `cost_est_aq` — only for "scoreable" macroblocks: those strictly inside the frame `(0 < x < mb_width-1 && 0 < y < mb_height-1)`, with a special case treating the whole frame as scoreable when `mb_width <= 2 || mb_height <= 2`.
- The AQ adjustment is `(cost * inv_qscale_factor + 128) >> 8`; with the neutral multiplier 256 this reduces approximately to `cost`, with rounding.

A `parallel_sum` reduction (from `x264-cl.h`) collapses each accumulator across the 256 lanes using the same local buffer three times. Thread `x==0` then writes `fenc_row_satds[y]` and atomically adds `cost_est` and `cost_est_aq` into `frame_stats[COST_EST]` and `frame_stats[COST_EST_AQ]`. `INTRA_MBS` is not touched by this kernel.

### 5.4 Host dispatch contract

`x264_opencl_lowres_init()` in `encoder/slicetype-cl.c`:

- Global dimensions for the intra kernel: `gdim[0] = ((mb_width+31)>>5)<<5` (padded to 32), `gdim[1] = 8*mb_height`; local dimensions fixed `[32,8]`.
- Arguments in order: `scaled_image2Ds[0]`, `intra_cost`, `frame_stats[last_buf]`, `lambda`, `mb_width`, `slow`.
- Row-sum kernel: global `[256, mb_height]`, local `[256,1]`, arguments `(intra_cost, inv_qscale_factor, row_satds[last_buf], frame_stats[last_buf], mb_width)`.
- Results are read back asynchronously into `fenc->lowres_costs[0][0]`, `fenc->i_row_satds[0][0]`, and `fenc->i_cost_est[0][0]` / `i_cost_est_aq[0][0]`.

### 5.5 GPU versus CPU output; host selection

The intra costs are lookahead estimates only. The host selects the GPU path when `h->param.b_opencl` is set and initialization succeeded; otherwise `slicetype.c` computes the same metadata on the CPU. The file's header claims the per-mode SATD values match the C versions exactly, but the surrounding pipeline (downscaled input, lambda choice, later mode selection) can still yield different frame-type decisions. The `slow` flag makes the GPU evaluate the same extra two modes the C lookahead evaluates at high `i_subpel_refine`, so the mode set is aligned. UNKNOWN: whether the `+5*lambda` penalty and the exact AQ rounding are bit-identical to the CPU's corresponding expressions on all inputs.

## 6. Dependencies

- **Uses from `x264-cl.h`:** `pixel`, `sum_t`, `sum2_t`, `COST_MAX`, `PIXEL_MAX`, `BITS_PER_SUM`, `HADAMARD4`, `HADAMARD4V`, `SATD_C_8x4_Q`, `abs2`, `parallel_sum`, `x264_clip_pixel`, `clamp_int` (defined locally in this file), the program sampler, and the local `atom_min` extension.
- **Input:** lowres luma image produced by `downscale.cl`; `inv_qscale_factor` produced either by host upload or `memset_int16`.
- **Consumers:** `bidir.cl::mode_selection` reads `fenc_intra_cost`; `sum_inter_cost` reads `inv_qscale_factor` and writes `frame_stats[INTRA_MBS]`; the host reads back `i_cost_est`, `i_cost_est_aq` and `i_row_satds` for rate control and frame-type scoring.
- **Host:** `common/opencl.c` creates both kernels by name; `encoder/slicetype-cl.c` dispatches them.

## 7. Constants and tables

- `CACHE_STRIDE` = 265, `BLOCK_OFFSET` = 266: one-column gutter plus one padding column, so a block starts at column 266 and a row's left neighbor is at column 265.
- Local size `[32,8]`: 32 macroblocks × 8 prediction modes, giving branch-free mode selection per wavefront.
- `33<<3 = 264` pixels and load threshold `(33<<3)>>2 = 66` texels: each texel fetch yields four pixels, so 66 fetches fill 264 cache columns.
- `5*lambda`: the fixed intra mode penalty applied to the best SATD, matching the C lookahead's bias against intra.
- `COST_MAX = 1<<28`: initial sentinel for the atomic minimum.
- `[1,2,1]/4` smoothing with bias 2 for top/left samples; `F1 = rhadd`, `F2 = (a+2b+c+2)>>2`.
- Planar constants: weight 17 on gradients, shift 5, bias 16, base offset `a - 3b - 3c + 16`.
- Scoreable macroblock rule: interior only, except when either dimension is ≤ 2.

## 8. Performance notes

- **Branch divergence:** the `switch(ly)` assigns one mode per work-item row, so all threads in a wavefront (same `ly`) take the same path; this is the central design idea and should be preserved in any reimplementation.
- **Local memory:** roughly 2385 bytes for the cache plus `top`/`left`/`left_top`/`cost_buf`; enough to be the dominant occupancy limiter for the intra kernel. Providing `HADAMARD4V` and vectorized predictions reduces private-register pressure on wide-register GPUs; the scalar path uses private `pixel[32]` buffers and is intended for single-width-register devices.
- **Coalescing:** cache loads use one `uint4` per work item into four consecutive columns, giving coalesced 16-byte reads from the image; left-edge loads are a narrow, uncoalesced special case.
- **Synchronization:** two barriers in the load/edge phase and one before writeback; atomic minima on local memory serialize up to eight writers per macroblock but avoid a separate reduction pass.
- **Platform limitations:** `VECTORIZE` is disabled for AMD Southern Islands/GCN (detected via `CL_DEVICE_SIMD_INSTRUCTION_WIDTH_AMD` returning 1) and for switchable-graphics devices; `atom_min` requires the extended local atomics extension.
- **Hotness:** intra analysis runs once per frame independent of preset; reducing the number of modes (`slow=0`) is the main preset-dependent cost saving.

## 10. Verification checklist

- For a constant-valued input image, every intra prediction mode should reproduce the same value, so `fenc_intra_cost[mb]` equals `5*lambda` (plus any fixed SATD of zero) for every macroblock.
- For a synthetic block with a known dominant direction, confirm the corresponding directional mode wins, i.e. the resulting cost is the minimum and is consistent with the chosen `slow` setting.
- Verify that with `slow=0` only eight modes are evaluated and the result equals the minimum over those eight; with `slow=1` it equals the minimum over all ten.
- Verify the cache edge padding: macroblocks at the left and top image borders use replicated edge samples and do not read out of bounds.
- Verify smoothed `top`/`left` samples follow the `[1,2,1]/4` filter with the documented index clamping.
- Verify `fenc_intra_cost` is written only for `gx < mb_width` and that padded work items produce no writes.
- Verify `frame_stats[COST_EST]`/`[COST_EST_AQ]` equal the sums of `cost`/`cost_aq` over scoreable macroblocks, and `fenc_row_satds[y]` equals the sum of `cost_aq` over the whole row.
- Verify AQ behaviour with `inv_qscale_factor = 256` versus a non-neutral value and check the `+128` rounding.
- Confirm vectorized and scalar builds (`VECTORIZE` on/off) produce identical `fenc_intra_cost` values for the same input frame.
