# `common/opencl/x264-cl.h`

**Role:** Shared compile-time foundation for every OpenCL kernel in the lookahead program: type aliases, cost/saturation constants, small vector helpers, the Hadamard/SATD primitives, a parallel reduction, and the motion-vector cost model.

> **Dirty-side behavioural specification.** Describes observable behaviour and structure only; no source text or near-verbatim pseudocode is reproduced.

---

## 1. Header

- Source path: `common/opencl/x264-cl.h`
- Role: supply the common definitions that all `.cl` files in `common/opencl/` rely on; the reference build concatenates this header with the `.cl` files into one OpenCL program source string.
- Marker: this document is a dirty-side behavioural specification derived from the reference implementation and public OpenCL/H.264 literature.

---

## 2. Purpose

The six `.cl` translation units are compiled as a single OpenCL program. They cannot include ordinary C headers (the device compiler sees only the program string), so this file provides a minimal, self-contained type system and math library for the device side. It establishes the exact numeric widths used by the analysis algorithms, the fixed-point cost format shared between kernels and the host, the saturation/clipping conventions that make GPU results comparable to the C lookahead, and the cheap Hadamard transform used by every SATD measurement.

Two decisions in this header are performance-critical and shape the whole design:

1. Distances are carried in 16-bit lanes packed two-per-32-bit word (`sum_t`/`sum2_t`), so one 32-bit register can hold two signed 16-bit residuals and the `abs2` trick can take both magnitudes in one instruction sequence.
2. Motion-vector cost is modelled with a logarithm so it can be evaluated with a handful of float ops rather than a table lookup; this approximation is intentionally shared by the hierarchical search and the sub-pixel refiners.

## 3. Public interface

There are no exported host symbols; everything here is device-side text. The surface consumed by the kernels is:

- **Extension pragma:** enables the `cl_khr_local_int32_extended_atomics` extension so that local-memory `min` atomics (`atom_min`) used by the intra kernel are available on conforming devices.
- **Sampler object:** a `constant sampler_t` configured for non-normalized coordinates, clamp-to-edge addressing and nearest filtering. Clamping is relied upon explicitly by motion-search kernels at frame borders; nearest filtering guarantees texel-exact reads.
- **Exact-width aliases:** `int8_t`, `uint8_t`, `int16_t`, `uint16_t`, `int32_t`, `uint32_t` (device analogues of the C standard types).
- **Domain aliases:** `pixel = uint8_t`, `sum_t = uint16_t`, `sum2_t = uint32_t`.
- **Constants:** `LOWRES_COST_MASK` = 16383 (`(1<<14)-1`), `LOWRES_COST_SHIFT` = 14, `COST_MAX` = `1<<28`, `PIXEL_MAX` = 255, `BITS_PER_SUM` = 16 (`8*sizeof(sum_t)`).
- **Frame-statistic indices:** `COST_EST` = 0, `COST_EST_AQ` = 1, `INTRA_MBS` = 2.
- **Macro `COPY2_IF_LT(x,y,a,b)`:** conditional update pair — if `y < x`, assign `x = y` and `a = b` together. Used wherever a new best cost must also record which prediction list produced it.
- **Constant array `dia_offs[4]`:** the four unit diamond steps in qpel-like units: `(0,-1)`, `(-1,0)`, `(1,0)`, `(0,1)` (up, left, right, down).
- **`pixel x264_clip_pixel(int x)`:** saturate to the legal luma range 0..255 and narrow to `pixel`.
- **`int2 x264_median_mv(short2 a, short2 b, short2 c)`:** component-wise median of three motion vectors, computed with min/max so no branch is needed.
- **`sum2_t abs2(sum2_t a)`:** branch-free absolute value of both 16-bit halves of a packed word, using sign-extension arithmetic; the two lanes are then available for independent summation.
- **`HADAMARD4(d0..d3,s0..s3)`** and **`HADAMARD4V(...)`:** the four-point Hadamard butterfly (sum/difference pairs, then sum/difference of those pairs). The `V` variant operates on `int2` lanes for the vectorized intra path.
- **`SATD_C_8x4_Q(name,q1,q2)`:** a macro that generates an 8×4 SATD function parametrized by the address-space qualifiers of its two pointers (`local`/`private` in practice). It forms four 8-wide residual rows, packs each row's first and second four differences into the low/high halves of `sum2_t`, applies the Hadamard butterfly along rows then columns, and returns the sum of absolute coefficients divided by two with the packed-lane correction `(low + high) >> 1`.
- **`int parallel_sum(int value, int x, volatile local int *array)`:** a work-group tree reduction. Each worker deposits its value in local memory, then repeatedly folds the upper half into the lower half with barriers only while the active width exceeds one warp/wavefront (32). Worker 0 receives the total in `array[0]`.
- **`int mv_cost(uint2 mvd)`:** the motion-vector rate model. For each component it computes `round(log2(|component|+1)*2 + 0.718 + (component!=0))` and returns the sum of the two rounded component costs as an integer.

## 4. State and data structures

- **`sampler`** is a program-scope constant, not a runtime argument; every image read in every kernel uses it. Its clamp mode is a correctness dependency, not merely a convenience.
- **`dia_offs`** is a read-only constant table placed in constant memory; all four diamond candidates are visible to every work item.
- **`sum_t`/`sum2_t`** define the fixed-point SATD format: each `sum2_t` holds two independent 16-bit signed sums. Accumulators are kept packed until the final `abs2` and normalization, halving register pressure and enabling two-way SIMD arithmetic.
- Cost saturation: any cost written back to a frame buffer is clamped with `min(cost, LOWRES_COST_MASK)` so it fits the low 14 bits of a 16-bit `lowres_costs` word; the upper two bits carry a `list_used` selector. `COST_MAX` is the initial "no candidate yet" sentinel used by the mode-selection and intra kernels.
- The frame-statistics buffer is a four-element `int` array per frame; indices 0..2 are the three statistics accumulated by the row-sum kernels, index 3 is initialized but not consumed by any kernel in this program (UNKNOWN: reserved or legacy).

Invariants: `BITS_PER_SUM` must remain 16 for the packing/unpacking arithmetic to be valid; the diamond table must stay ordered so that `(cost & 3)` can be used directly as the index of the winning direction.

## 5. Algorithm / behaviour

### 5.1 Packing and SATD

The Hadamard butterfly is the standard separable 4×4 transform scaled so that no explicit division occurs until the end. The `abs2` helper exploits two's complement: it derives a mask from the sign bits of both 16-bit lanes, conditionally negates both, and leaves the magnitudes in the two halves. The generic 8×4 SATD generator assembles eight columns of residuals from two pointers with configurable strides, transforms the four rows, transforms the four resulting columns, sums the eight absolute coefficients per lane pair, and finally adds the two 16-bit accumulators before a single logical shift right by one. That final halving is the normalization required because the unscaled Hadamard matrix doubles the energy twice.

The vectorized intra path uses the `HADAMARD4V` variant on `int2` lanes and swizzles the eight loaded pixels into four 2-component vectors, so one transform handles two horizontal pixels at once. Both paths implement the same mathematical SATD; the source states they produce identical results.

### 5.2 Motion-vector cost model

`mv_cost` converts a two-component qpel motion-vector difference into an approximate number of bits. Adding one before taking `log2` avoids the undefined logarithm of zero; scaling by two and adding a constant approximates the exponential-Golomb code length used by H.264 for motion-vector differences. A further term of one is added per non-zero component, reflecting the sign bit that must be transmitted. Each component is rounded independently to an integer before summation, so the result is a cheap integer penalty that can be multiplied by `lambda` and compared directly against distortion costs.

### 5.3 Parallel reduction

The reduction is a standard interleaved tree in local memory. Because barriers are omitted below 32 threads, correctness relies on the host launching these kernels with a work-group X dimension that is a multiple of the hardware warp/wavefront size (the host uses 256 for the row-sum kernels). The same local array is reused for four separate reductions in sequence, with a barrier at the start of each ensuring the previously stored values are visible.

### 5.4 GPU versus CPU output; host selection

This header defines no kernels and produces no output itself. It fixes the numeric conventions that make GPU analysis metadata comparable to CPU analysis metadata: pixel clipping, cost saturation, cost format, and the MV rate model. The host does not check bit-exact equality between the two lookahead implementations; it chooses the GPU path solely on the `b_opencl` parameter and successful OpenCL initialization (see the dispatch documentation for `bidir.cl` and `motionsearch.cl`). Any difference in the values produced by these helpers changes only lookahead estimates such as `lowres_costs`, `lowres_mvs` and `i_cost_est`, not reconstructed samples. UNKNOWN: whether the reference project guarantees that GPU and CPU lookahead make identical frame-type decisions in all cases.

## 6. Dependencies

- **Included by:** all six `.cl` files. The reference host concatenates this text ahead of the kernel sources when creating the OpenCL program.
- **Depends on:** the OpenCL 1.1 C language (image reads, local memory, extended atomics extension, vector types, built-ins `rhadd`, `abs_diff`, `clamp`, `round`, `log2`, `convert_*_sat`, `as_uint`, `atom_min`, `barrier`).
- **Host-side linkage:** `common/opencl.c` builds the program with an optional `-DVECTORIZE=1` flag, which selects the `HADAMARD4V`-based intra implementations; the constants in this header are independent of that flag.

## 7. Constants and tables

- `LOWRES_COST_MASK` (16383) and `LOWRES_COST_SHIFT` (14): reserve the low 14 bits for a saturated cost and the next two bits for a list identifier; four list identifiers (0=intra, 1=list0, 2=list1, 3=bidir) fit exactly.
- `COST_MAX` (268435456): a sentinel far above any plausible SATD/SAD sum, guaranteeing that the first real candidate wins the `COPY2_IF_LT` comparison.
- `PIXEL_MAX` (255): 8-bit luma range. All kernels operate on 8-bit samples; higher bit depths are not handled by this OpenCL path (UNKNOWN: behaviour for 10-bit source — the reference build uses `CL_UNSIGNED_INT8` image formats).
- `BITS_PER_SUM` (16): the boundary between the two packed 16-bit lanes; every shift, mask and `abs2` operation is derived from it.
- `dia_offs`: the canonical four-neighbour diamond used by both hierarchical motion estimation and sub-pixel refinement; ordering is fixed because the winning index is encoded in the low two bits of a packed cost.
- Statistic indices 0/1/2: `COST_EST`, `COST_EST_AQ`, `INTRA_MBS` — the three values read back by the host for rate control and frame-type scoring.

## 8. Performance notes

- Packing two 16-bit sums into one 32-bit word halves the number of accumulators and lets `abs2` produce two absolute values with a handful of integer ops; this is the main reason the SATD code is branch-light.
- `mv_cost` deliberately uses transcendental float operations per candidate rather than a lookup table; on GPUs with fast special-function units this avoids local-memory or global-memory table traffic. UNKNOWN: relative cost on devices with poor `log2` throughput.
- `parallel_sum` avoids barriers for the final warp, reducing synchronization cost; a host launch with fewer than 32 threads per group would break this assumption (the host always uses 256 for row sums).
- `atom_min` on local memory requires the extended-atomics extension; devices lacking it cannot compile the intra kernel (the reference enables the extension pragma unconditionally).
- Coalescing: the header itself performs no memory access, but the vector helpers encourage consecutive 4-byte/8-byte reads in the intra kernel.
- Platform limitations: the reference flags AMD Southern Islands as "single-width register" devices and disables `VECTORIZE` for them; the scalar code path in `intra.cl` is the fallback. Intel/AMD switchable-graphics devices are disabled entirely at initialization.

## 10. Verification checklist

- Confirm `abs2` returns the exact magnitude of each independent 16-bit lane for positive, negative and saturated inputs, including the value `-32768` (which overflows two's-complement negation — UNKNOWN whether the reference tolerates this).
- Confirm `x264_clip_pixel` clamps below 0 to 0, above 255 to 255, and passes 0/255 through unchanged.
- Confirm `x264_median_mv` returns the component-wise median for all six orderings of three arbitrary 2D vectors.
- Confirm `HADAMARD4`/`HADAMARD4V` produce the standard unnormalized 4-point butterfly (outputs are sums/differences of sums/differences).
- Confirm the generated 8×4 SATD routine returns the same value as a scalar reference SATD for random 8×8 blocks, including the final `>>1` normalization.
- Confirm `parallel_sum` returns the sum of all `local_size(0)` inputs when launched with a 256-wide group, and that four consecutive calls reuse the same buffer correctly.
- Confirm `mv_cost` is monotone non-decreasing in each component and that a zero vector returns the smallest possible value.
- Confirm `COPY2_IF_LT` updates both outputs atomically with respect to the comparison (no partial update when the condition is false).
