# `common/ppc/predict.c` — PowerPC intra-prediction implementation

## 1. Header

- **Source path:** `common/ppc/predict.c`.
- **Role in one sentence:** AltiVec implementations of the 16x16 luma plane/DC/horizontal/vertical predictors and the 8x8 chroma plane predictor, plus their dispatchers.
- **Marker:** Dirty-side behavioural specification; all descriptions are behavioural and written independently of the reference source.


## 2. Purpose

PowerPC accelerates the most compute-intensive intra modes. Directional copying and DC averaging are already cheap in scalar code, so only the plane modes and the full set of 16x16 modes are implemented with vectors.

## 3. Public interface

Exported initializers (declared in `ppc/predict.h`):

- `void x264_predict_16x16_init_altivec( x264_predict_t pf[7] )`
- `void x264_predict_8x8c_init_altivec( x264_predict_t pf[7] )`

All predictor routines are file-local. The 16x16 set covers vertical, horizontal, DC, plane, DC-left, DC-top and DC-128; the chroma set covers only plane mode.

## 4. State and data structures

All routines are stateless. Destination blocks use `FDEC_STRIDE = 32`. The plane-mode kernels use `vec_s16_u` unions to insert scalar gradient parameters into vector lanes, then broadcast them with `vec_splat`. A constant vector `induc_v` holds column indices 0..7; a second vector for indices 8..15 is derived by doubling the broadcast slope.

## 5. Algorithm / behaviour

**16x16 plane mode.** Horizontal and vertical gradients are computed as weighted sums of symmetric neighbor pairs with weights 1..8, matching `(5H+32)>>6` and `(5V+32)>>6` from the generic implementation. The base value is `a = 16*(top-right + bottom-left)`. The corner coefficient is `i00 = a - 7*b - 7*c + 16`. Each row is generated from `i00 + x*b` for x in 0..7 and `i00 + 8*b + x*b` for the second half, shifted right by 5 with rounding and packed to bytes with saturation. `c` is accumulated into the row base after each row.

**8x8 chroma plane mode.** Gradients use four pairs with weights 1..4, producing `b = (17H+16)>>5` and `c = (17V+16)>>5`. The base coefficient is `a - 3*b - 3*c + 16`. Each row of eight bytes is generated from `i00 + x*b` for x in 0..7, shifted right by 5 and packed with saturation.

**DC modes.** Neighbor samples are summed in scalar registers, rounded with `(sum+16)>>5` for the full 16x16 case and `(sum+8)>>4` for one-sided cases, splatted into a vector, and written with eight stores per block using the `PREDICT_16x16_DC_ALTIVEC` helper macro. The 128 variant generates the constant by shifting a splat of 1 left by 7 bits.

**Horizontal mode.** Sixteen 16-byte loads are taken from `pix-1` on each row, the last byte of each is splatted across a vector, and the result is stored to the row. This reproduces left-sample replication.

**Vertical mode.** Four 32-bit words are read from the row above and assembled into one vector, which is stored to all sixteen rows.

**Dispatch.** `x264_predict_16x16_init_altivec` installs all seven entries; `x264_predict_8x8c_init_altivec` installs only the plane entry. Assignments are compile-time guarded for 8-bit builds.

## 6. Dependencies

- Includes `common/common.h`, `ppccommon.h`, local `predict.h`, and `common/pixel.h`.
- Called from the generic prediction dispatchers in `common/predict.c`.
- Uses `VEC_STORE8` and vector helpers from `ppccommon.h`.

## 7. Constants and tables

- `FDEC_STRIDE = 32`.
- 16x16 plane: weights 1..8, scaling `(5*H+32)>>6`, corner offset `a - 7b - 7c + 16`, final shift 5.
- 8x8 chroma plane: weights 1..4, scaling `(17*H+16)>>5`, corner offset `a - 3b - 3c + 16`, final shift 5.
- DC rounding: `(sum+16)>>5` combined, `(sum+8)>>4` one-sided.

## 8. Performance notes

The plane kernels avoid per-pixel multiplication by maintaining a running slope vector, which is the main vectorization gain. DC and vertical modes are essentially memory-fill operations. The reference source notes that only the chroma plane mode was worth vectorizing for 8x8 chroma. Clean implementations should reproduce the exact rounding and clipping behaviour before optimizing.

- Every installed routine matches the generic C predictor byte for byte.
- Plane output is clipped to 0..255.
- DC rounding matches for combined and one-sided neighbor sets.
- Destination rows outside the block are untouched.
- The correct subset of function-table entries is installed.
