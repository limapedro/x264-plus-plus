# common/x86/mc-a2.asm — behavioural specification

**Role:** second x86 MC file: half-pel filter generation (V/H/C and fused), non-temporal plane copy/swap/interleave/deinterleave (including RGB and v210), aligned memcpy/memzero, integral-image initialisation, low-resolution frame preparation for MB-tree, and MB-tree propagate-cost/list/fix8 kernels.
**Marker:** dirty-side behavioural specification.

---

## 1. Header

- Source path: `common/x86/mc-a2.asm`
- Role: provides the SIMD building blocks used by half-pel interpolation, frame analysis (SATD/integral), lookahead (MB-tree), and 4:4:4/RGB input handling.
- Contains both 8-bit and high-depth paths; `mc-a.asm` holds the avg/weight/copy/chroma kernels and `mc-c.c` composes them.

---

## 2. Purpose

Before quarter-pel interpolation can run, four half-pel planes must be generated by applying the H.264 6-tap `[1,−5,20,20,−5,1]` filter vertically, horizontally and centrally (the "C" 6-tap-after-5-tap intermediate). Doing this per macroblock would be wasteful, so x264 precomputes full H/V/C planes once per reference frame. This file implements those filters plus the plane-format conversion and lookahead kernels that surround them.

---

## 3. Public interface

- `void hpel_filter( uint8_t/uint16_t *dsth, *dstv, *dstc, *src, intptr_t stride, int width, int height, int16_t *buf )` — C-composed driver (in `mc-c.c`) that calls the following per-row kernels:
  - `hpel_filter_v( dst, src, buf, stride, width )` — vertical 6-tap filter producing one row into `dst` and a signed 16-bit intermediate into `buf`.
  - `hpel_filter_c( dst, buf, width )` — horizontal filter of the signed intermediate into the diagonal (C) half-pel plane.
  - `hpel_filter_h( dst, src, width )` — horizontal 6-tap filter of the original row into the H plane.
- `void plane_copy{,_swap}{,_core}( dst, i_dst, src, i_src, w, h )` — non-temporal row copy, optionally swapping adjacent byte pairs.
- `void plane_copy_interleave_core( dst, i_dst, srcu, i_srcu, srcv, i_srcv, w, h )`, `store_interleave_chroma( dst, i_dst, srcu, srcv, height )` — U/V interleaving.
- `void plane_copy_deinterleave{,_yuyv,_rgb,_v210}(...)` — deinterleaving to planar formats (RGB and v210 only in high-depth for v210).
- `void load_deinterleave_chroma_{fenc,fdec}( dst, src, i_src, height )` — deinterleave chroma into fenc/fdec stride layouts.
- `void *memcpy_aligned( dst, src, n )`, `void memzero_aligned( dst, n )` — restricted aligned-memory helpers (n multiple of 16 / 128).
- `void integral_init4h( sum, pix, stride )`, `integral_init8h`, `integral_init4v( sum8, sum4, stride )`, `integral_init8v( sum8, stride )` — horizontal/vertical prefix sums for the successive-elimination SATD prefilter (8-bit only for the *h variants).
- `void frame_init_lowres_core( src0, dst0, dsth, dstv, dstc, src_stride, dst_stride, width, height )` — produce 2× downsampled H/V/C planes for MB-tree lookahead.
- `void mbtree_propagate_cost( dst, propagate_in, intra_costs, inter_costs, inv_qscales, fps_factor, len )` — accumulate propagation costs in float and write rounded int16.
- `void mbtree_propagate_list_internal( ... )` — distribute a propagation amount to four neighbouring lowres blocks bilinearly (signature varies by ISA; see `mc-c.c`).
- `void mbtree_fix8_pack( dst, float *src, count )` / `mbtree_fix8_unpack( float *dst, uint16_t *src, count )` — convert between float costs and 8-bit fixed-point (Q8) representation.

## 4. State and data structures

- Half-pel filters use a signed 16-bit scratch `buf` holding the vertically summed neighbour rows; `buf+16` is passed to avoid overlap with alignment loading.
- Constants in rodata: `pw_1024`, `filt_mul20` (32 bytes of 20), `filt_mul15` (1,−5), `filt_mul51` (−5,1), `hpel_shuf`, `pad10/20/30`, `depad`, `tap1/2/3`, `pf_256`, `pf_inv16777216`, v210/RGB/mbtree shuffle masks.
- `HIGH_BIT_DEPTH` changes pixel size to 16 bits and therefore the filter/rounding constants (`pw_16`/`pw_1` for rounding, `[pw_pixel_max]` clipping).
- `PREFETCHNT_ITER` issues `prefetchnta` four iterations ahead in 64-byte steps (4×`mmsize` per iteration).

## 5. Algorithm / behaviour

### 5.1 Half-pel filter math (all depths)
For a row of samples `a,b,c` at offsets −2,0,+2 from the current position (after symmetric neighbour addition for the vertical pass), the 6-tap output is `(a − 5b + 20c) >> shift` with rounding. `FILT_V2` computes `a−5b+20c` on two vectors using shifts/subtracts; `FILT_H`/`FILT_H2` implement a low-precision variant using repeated `(a−b)/4` steps because the vertical stage is pre-rounded. `FILT_PACK` either uses SSSE3 `pmulhrsw` with a scaling/rounding vector or adds a rounding constant and shifts (`psraw`, or `psubusw`+`psrlw` for the unsigned-corrected variant), then packs to bytes for 8-bit.

- `hpel_filter_v`: reads three rows above and three below the current row (via `lea r5,[r1+r3]` and `sub r1,r3,r3`), adds symmetric pairs, applies `FILT_V2`, stores the signed intermediate to `buf` and the rounded/clipped result to `dstv`. High-depth loads `pad10/20/30` into registers to correct the 10-bit range and clips to `[0, PIXEL_MAX]`.
- `hpel_filter_c`: reads six consecutive words from `buf` and applies `pmaddwd` with `tap1=[1,−5]`, `tap2=[20,20]`, `tap3=[−5,1]` plus `depad`, shifts right 10, combines two dword streams, clips and stores. This produces the C plane (diagonal half-pel).
- `hpel_filter_h`: uses `palignr` (or `movh`/`punpcklbw` on older ISAs) to fetch the six horizontal neighbours, applies `pmaddubsw` with `filt_mul15`/`filt_mul51`/`filt_mul20` on SSSE3 (or `FILT_H2` otherwise), rounds with `pw_1024`/`pw_1`, shuffles to byte order with `hpel_shuf`, and stores with a non-temporal move.
- Fused `hpel_filter` (x86-64 only, 8-bit): `DO_FILT_V`, `DO_FILT_C`, `DO_FILT_H` run the three stages in one pass over a row, keeping vertical intermediates in registers (`m8/m7/m13` etc.) and switching the rounding vector `m15` between `pw_512` (V/H) and `pw_1024` (C) with `psrlw`/`paddw` between passes. Instantiated for SSE2, SSSE3, AVX and AVX2.

### 5.2 Plane copy / swap
`PLANE_COPY_CORE` processes four `mmsize` chunks per iteration with `movu` loads and `movnta` (non-temporal) stores, prefetching four iterations ahead; optional `pshufb` with `copy_swap_shuf` swaps adjacent words/bytes. It assumes `i_dst` and `w` are multiples of `mmsize` and `i_dst > w`. `PLANE_COPY_AVX512` adds tail handling with masked `vmovdqu8/16/32 {k1}{z}` (mask derived from `w&15` or `w&31`) and three size regimes: >256 bytes/row (four 64-byte chunks + masked tail), 65–256 (temporal stores), 1–64 (masked single vector). A final `sfence` orders the non-temporal stores.

### 5.3 Interleave / deinterleave
`INTERLEAVE` combines one U row and one V row into an interleaved UV row with `punpcklbw`/`punpckhwd`, storing with non-temporal moves; used by `plane_copy_interleave_core` which pads the remainder of each destination row with copies of the last vector. `DEINTERLEAVE` splits an interleaved row into U and V with `pshufb` (`deinterleave_shuf`) on SSSE3/AVX2, or `pand`/`psrlw`/`packuswb` on SSE2; for mmsize 32 it additionally uses `vpermq q3120`. `plane_copy_deinterleave` may write up to 15 pixels past each output plane (documented in `mc.h`). `load_deinterleave_chroma_{fenc,fdec}` deinterleaves into the fenc/fdec stride layouts, with AVX2/AVX-512 variants that assemble four source rows into one/two vectors with `vinserti128`/`vinserti32x4` and masked stores.

### 5.4 RGB and v210 deinterleave
`PLANE_DEINTERLEAVE_RGB_CORE` handles 3-byte (BGR) and 4-byte (BGRA) interleaved input, using `pshufb` with `deinterleave_rgb_shuf` (SSSE3) or a butterfly sequence (SSE2) to separate channels into three planes. AVX2 uses `vpermd` with `deinterleave_shufd`. `PLANE_DEINTERLEAVE_V210` (high depth) converts 10-bit v210 4:2:2 packed 32-bit words into 16-bit Y and U/V planes using masks (`v210_mask`), byte shuffles and `pmulhrsw` with `v210_mult` (or AVX-512 `vpsrlvw`/`vpermt2w` and `vpbroadcastd` masks).

### 5.5 memcpy / memzero
`MEMCPY` copies from the end backwards in one/two vector chunks, requiring `n` a multiple of `mmsize` and aligned pointers. `MEMZERO` zeroes in 128-byte blocks. The AVX-512 `memcpy_aligned` uses a masked tail (`rorx`, `not`, `shrx`, `kmovw`) then 64-byte chunks; `memzero_aligned` AVX-512 zeroes 64 bytes per iteration.

### 5.6 Integral images
- `integral_init4h`: uses `mpsadbw` with control 0 to compute four pixel sums at once (sum of 4 consecutive bytes) from a 16-byte row, adds the previous row's cumulative sum, writes to `sum`. AVX2 uses `vinserti128` to handle 32 bytes.
- `integral_init8h`: additionally computes 8-pixel sums with `mpsadbw` control `100100b`/`100b`, adds both 4- and 8-sums to the previous row.
- `integral_init4v`/`8v`: compute vertical differences between rows 8 apart (`sum8`) and 4 apart (`sum4`) using `psubw`/`paddw` on word vectors, with SSE2 `shufpd` or SSSE3 `palignr`/AVX2 `paddw` variants. Only enabled for 8-bit.

### 5.7 Low-resolution frame init
`frame_init_lowres_core` walks the source from the bottom-right backwards, generating four downsampled planes from 2×2 source blocks: `dst0 = avg` of four pixels, `dsth = avg` of the two horizontal pairs, `dstv = avg` of the two vertical pairs, `dstc = avg` of the diagonal pairs. The macros `FILT8x4`, `FILT32x4U`, `FILT16x2`, `FILT8x2U`, `FILT8xU`, `FILT8xA` implement the various width/ISA combinations, with `PALIGNR` for shifted pairs and `packuswb`/`packssdw` for packing. High depth uses `pavgw` and dword masks. `dst_gap`/`src_gap` are pushed on the stack to handle the padding at row ends.

### 5.8 MB-tree kernels
- `mbtree_propagate_cost`: for each element computes `dst = (propagate + intra*inv_q*fps_factor) * (intra−inter) / intra`, clipped to int16. SSE2/FMA4 use Newton–Raphson reciprocal approximation (`rcpps` + two refinement mults); AVX2 uses `pmovzxwd` and FMA; AVX-512 uses exact `vdivps {rn-sae}` and `vpmovsdw`.
- `mbtree_propagate_list_internal`: for each MV, scales `propagate_amount` by `bipred_weight` when three lists are used, computes the MB coordinates from `(x,y)>>5`, then distributes the amount to four neighbours with bilinear weights `(32−x)(32−y)`, `x(32−y)`, `(32−x)y`, `xy` using `pmulhrsw` (rounding `/1024`). The AVX-512 variant adds bounds checks (`vpcmpuw`/`vpcmpud`), masked `vpgatherdd`/`vpscatterdd` with conflict resolution via `vpconflictd`/`vplzcntd`/`vpermd` — a sophisticated way to accumulate multiple contributions to the same lowres block in parallel.
- `mbtree_fix8_pack`/`unpack`: convert floats to 8-bit fixed point (multiply by 256, truncate, byte-swapped word store) and back (multiply by 2^−24). AVX-512 uses masked tail stores.

### 5.9 Dispatch
`mc-c.c` installs: MMX2 for hpel/plane copy/integral/lowres/mbtree baselines; SSE/SSE2/SSSE3/AVX/AVX2/AVX-512 progressively override plane copy, interleave, deinterleave, hpel, integral and mbtree functions. `X264_CPU_CACHELINE_32/64` picks `cache32_mmx2` lowres; `SLOW_PSHUFB`/`SLOW_PALIGNR` disable certain SSSE3 variants.

## 8. Performance notes

- Half-pel filtering is memory-bandwidth bound; non-temporal stores avoid polluting cache with planes that will be read once by ME. The fused `hpel_filter` keeps intermediates in registers across the three passes, saving `buf` traffic.
- Plane copy uses four-vector unrolling and `prefetchnta` four iterations ahead to hide memory latency; AVX-512 masked tails avoid scalar cleanup.
- MB-tree propagate cost is compute-bound; FMA3/4 and exact AVX-512 division remove the reciprocal-approximation error and shorten the dependency chain.
- The AVX-512 propagate-list gather/scatter with conflict resolution is the most complex kernel here: it handles duplicate destination offsets in `ceil(log2(n))` parallel steps rather than serialising.

**AVX2/AVX-512 vectorization opportunities and bottlenecks (with references):**
- AVX-512 half-pel filtering can use `vpermt2w`/`vpsrlvw` (as the v210 path does) to replace multiple `pshufb` steps; the reference only uses these for v210, so a rebuild could extend them to hpel (UNKNOWN profitability).
- `vpgatherdd`/`vpscatterdd` on AVX-512 are the key to the mbtree propagate-list speedup, but they are slow on some microarchitectures when conflicts are frequent; the reference's `vpconflictd` loop mitigates correctness, not throughput (Intel Optimization Reference Manual).
- Masked non-temporal stores for plane-copy tails exist only for SSE/AVX2 paths; AVX-512 `vmovdqu8 {k}{z}` eliminates them (Intel Intrinsics Guide).
- Bottleneck: `pmaddwd`/`pmulhrsw` in hpel have fixed 5-cycle latency chains on some CPUs; interleaving V and C passes (as the fused macro does) hides this.
- Frequency throttling for wide vectors as noted previously (Intel Optimization Reference Manual).

## 10. Verification checklist

1. Half-pel filters: feed a random row with known neighbour context and compare `hpel_filter_v/c/h` outputs against a scalar implementation of the H.264 6-tap filter with the same rounding/clipping; test 8- and 10-bit.
2. Fused vs split: for x86-64 8-bit builds, verify `hpel_filter` produces bit-identical dsth/dstv/dstc to the split `init` path for random frames.
3. Plane copy/swap: verify exact copy and that swapped output equals pairwise byte/word swap; verify non-temporal stores are ordered by an `sfence`.
4. Interleave/deinterleave round-trip: deinterleave an interleaved UV row and re-interleave to recover the original; check RGB 3/4-byte and v210 10-bit conversions against scalar references.
5. memcpy/memzero: verify for legal sizes (multiples of 16/128) and aligned pointers; confirm no overrun at the end.
6. Integral images: compare `integral_init4h/8h/4v/8v` outputs against a scalar prefix-sum implementation.
7. Lowres init: verify each of the four output planes against scalar 2×2 averaging with the reference rounding.
8. MB-tree: verify propagate cost/list/fix8 against scalar formulas for random inputs, including the bilinear weights and the AVX-512 gather/scatter path with duplicate offsets.
9. Force ISA levels with CPU flags and run `checkasm` for all instantiated variants.

## 11. Open questions

- Whether `mbtree_propagate_list_internal_avx512` handles all `list_mask` values correctly is UNKNOWN; it uses `vptestmw` against a shifted mask that depends on `LOWRES_COST_SHIFT`.
- AVX-512 `memcpy_aligned` uses `rorx`/`shrx` (BMI2) — UNKNOWN whether callers guarantee BMI2 when AVX-512 is set (AVX-512 CPUs normally do, but a rebuild should check the CPU flags).
- Some functions are only instantiated for certain bit depths (e.g. `integral_init4h` 8-bit only); UNKNOWN if any caller in a high-depth build expects them.
