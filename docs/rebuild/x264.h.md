# x264.h — rebuild specification

## 1. Header

- Source path: `x264.h` (root of the reference tree), the single public header of libx264.
- Role: declares the complete application-facing API — opaque encoder handle, parameter and picture structures, NAL representation, level limits, all constants, and all exported functions.
- Marker: **dirty-side behavioural specification** — interface semantics and structure, never source text.

## 2. Purpose

This header is the stable contract between libx264 and every application that uses it (the bundled CLI, the `example.c` demo, FFmpeg, and third-party muxers). It hides the encoder internals behind `x264_t`, exposes configuration through one large plain-data `x264_param_t`, exposes frames through `x264_picture_t`, and exposes encoded bytes through `x264_nal_t`. It also encodes ABI compatibility in two ways: a build-number macro that is concatenated into the `x264_encoder_open` symbol name, and platform import/export annotations for shared-library builds. Everything an application can legally observe is declared here; anything else is internal.

## 3. Public interface

### 3.1 Versioning and linkage

- `X264_BUILD` — `164`. The API version. It is concatenated into the encoder-open symbol name so that an application compiled against one API version fails to link against an incompatible library rather than crashing at runtime. `X264_VERSION` and `X264_POINTVER` are added by the generated `x264_config.h` (see `version.sh.md`).
- `X264_API` — resolves to one of three things depending on build macros: on Windows with `X264_API_IMPORTS` defined it is `__declspec(dllimport)`; with `X264_API_EXPORTS` it is `__declspec(dllexport)`; otherwise empty. On non-Windows GNU compilers of version 4+, export is `visibility("default")`; elsewhere empty.
- `x264_t` — opaque encoder handle type; applications never inspect its contents.
- The header is wrapped in `extern "C"` for C++ consumers.
- It warns (or emits an MSVC pragma message) when none of the standard fixed-width-integer header guard macros are defined, because it relies on `uint8_t`/`int64_t` being available. It includes `<stdarg.h>` and the generated `x264_config.h` itself.

### 3.2 NAL units

Enums:

- `enum nal_unit_type_e`: `NAL_UNKNOWN=0`, `NAL_SLICE=1`, `NAL_SLICE_DPA=2`, `NAL_SLICE_DPB=3`, `NAL_SLICE_DPC=4`, `NAL_SLICE_IDR=5`, `NAL_SEI=6`, `NAL_SPS=7`, `NAL_PPS=8`, `NAL_AUD=9`, `NAL_FILLER=12`. The comment-level convention is that types 6, 9, 10, 11 and 12 have `ref_idc == 0` and IDR slices have non-zero `ref_idc`.
- `enum nal_priority_e`: `DISPOSABLE=0`, `LOW=1`, `HIGH=2`, `HIGHEST=3`.

`typedef struct x264_nal_t` fields and contracts:

| Field | Type | Meaning |
| --- | --- | --- |
| `i_ref_idc` | int | NAL reference priority, one of `nal_priority_e` |
| `i_type` | int | NAL unit type, one of `nal_unit_type_e` |
| `b_long_startcode` | int | Whether a four-byte Annex-B start code was used |
| `i_first_mb` | int | For slice NALs, index of the first macroblock in the slice |
| `i_last_mb` | int | For slice NALs, index of the last macroblock in the slice |
| `i_payload` | int | Payload size in bytes including padding |
| `p_payload` | uint8_t* | Byte stream; with `b_annexb` set it starts with a start code, otherwise the first four bytes are a big-endian size equal to `i_payload-4` |
| `i_padding` | int | Number of padding bytes inside the payload |

Lifetime: all NAL data, including the payload pointer, becomes invalid after the next call to `x264_encoder_encode` or `x264_encoder_headers`; callers must consume or copy it before re-entering the encoder. Payloads returned by a single call are contiguous in memory.

### 3.3 Parameter structure (`x264_param_t`)

The structure is grouped by concern. Field names, types and semantics:

**CPU / threading**

| Field | Type | Semantics |
| --- | --- | --- |
| `cpu` | uint32_t | Bitmask of `X264_CPU_*` flags; normally from CPU detection or `--asm` |
| `i_threads` | int | Number of parallel encoder threads; `0` = automatic |
| `i_lookahead_threads` | int | Threads dedicated to lookahead; `0` = automatic |
| `b_sliced_threads` | int | Slice-based threading instead of frame-based |
| `b_deterministic` | int | Reject non-deterministic threaded optimizations |
| `b_cpu_independent` | int | Force canonical algorithms rather than CPU-specific choices |
| `i_sync_lookahead` | int | Threaded lookahead buffer size; `-1` = automatic |

**Video properties**

`i_width`, `i_height`, `i_csp`, `i_bitdepth`, `i_level_idc` (negative = derive from stream), `i_frame_total` (0 = unknown), `i_nal_hrd` (`X264_NAL_HRD_*`). The `vui` substructure carries `i_sar_width`/`i_sar_height` (reduced to coprime values with each <= 65535), `i_overscan` (0 undef, 1 no overscan, 2 overscan), `i_vidformat`, `b_fullrange`, `i_colorprim`, `i_transfer`, `i_colmatrix`, `i_chroma_loc` (both top and bottom). VUI values follow H.264 Annex E enumerations.

**Bitstream**

| Field | Semantics |
| --- | --- |
| `i_frame_reference` | Maximum reference frames |
| `i_dpb_size` | Force a DPB larger than implied by refs/B-frames (error-resilience fallback) |
| `i_keyint_max` | Maximum GOP length; `1<<30` = infinite |
| `i_keyint_min` | Minimum GOP length; `0` = automatic |
| `i_scenecut_threshold` | Extra-I-frame aggressiveness |
| `b_intra_refresh` | Periodic intra refresh instead of IDR |
| `i_bframe`, `i_bframe_adaptive`, `i_bframe_bias`, `i_bframe_pyramid` | B-frame count, adaptation mode, bias, and reference-B mode |
| `b_open_gop`, `b_bluray_compat` | Recovery-point GOPs and Blu-ray compatibility constraints |
| `i_avcintra_class`, `i_avcintra_flavor` | AVC-Intra profile selection |
| `b_deblocking_filter`, `i_deblocking_filter_alphac0`, `i_deblocking_filter_beta` | Loop filter enable and two offsets in [-6,6], -6 light / 6 strong |
| `b_cabac`, `i_cabac_init_idc` | Entropy coder selection and table index |
| `b_interlaced`, `b_constrained_intra` | Interlaced coding and constrained intra prediction |
| `i_cqm_preset`, `psz_cqm_file`, `cqm_4iy[16]`, `cqm_4py[16]`, `cqm_4ic[16]`, `cqm_4pc[16]`, `cqm_8iy[64]`, `cqm_8py[64]`, `cqm_8ic[64]`, `cqm_8pc[64]` | Quantization matrix preset/filename and eight custom matrices (4x4 luma/chroma intra/inter, 8x8 luma/chroma intra/inter) |

**Logging / debug**

`pf_log` — callback with signature `void (*)(void*, int, const char*, va_list)`; `p_log_private` — opaque caller data passed to it; `i_log_level` — `X264_LOG_*` threshold; `b_full_recon` — force full reconstruction even where not needed for encoding; `psz_dump_yuv` — filename for writing reconstructed frames (implies full reconstruction).

**Analysis substructure (`analyse`)**

`intra` and `inter` — bitmasks of `X264_ANALYSE_*` partition sets; `b_transform_8x8`; `i_weighted_pred`; `b_weighted_bipred`; `i_direct_mv_pred`; `i_chroma_qp_offset`; `i_me_method`; `i_me_range`; `i_mv_range` (-1 = from level); `i_mv_range_thread` (-1 = from thread count); `i_subpel_refine`; `b_chroma_me`; `b_mixed_references`; `i_trellis`; `b_fast_pskip`; `b_dct_decimate`; `i_noise_reduction`; `f_psy_rd`; `f_psy_trellis`; `b_psy`; `b_mb_info`; `b_mb_info_update`; `i_luma_deadzone[2]` (inter, intra); `b_psnr`; `b_ssim`.

**Rate-control substructure (`rc`)**

`i_rc_method` (`X264_RC_*`), `i_qp_constant` (0 = lossless), `i_qp_min`, `i_qp_max`, `i_qp_step`, `i_bitrate`, `f_rf_constant`, `f_rf_constant_max`, `f_rate_tolerance`, `i_vbv_max_bitrate`, `i_vbv_buffer_size`, `f_vbv_buffer_init` (<=1 is a fraction of buffer size, >1 is kbit), `f_ip_factor`, `f_pb_factor`, `b_filler`, `i_aq_mode`, `f_aq_strength`, `b_mb_tree`, `i_lookahead`, `b_stat_write`, `psz_stat_out`, `b_stat_read`, `psz_stat_in`, `f_qcompress` (0 constant bitrate, 1 constant QP), `f_qblur`, `f_complexity_blur`, `zones`, `i_zones`, `psz_zones`.

**Cropping, SEI and muxing**

`crop_rect` with `i_left`/`i_top`/`i_right`/`i_bottom` added to implicit non-mod16 cropping; `i_frame_packing`; `mastering_display` substructure (`b_mastering_display`, six chromaticity coordinates in units of 0.00002, `i_display_max`/`i_display_min` in 0.0001 cd/m²); `content_light_level` (`b_cll`, `i_max_cll`, `i_max_fall`); `i_alternative_transfer`; `b_aud`; `b_repeat_headers`; `b_annexb`; `i_sps_id`; `b_vfr_input`; `b_pulldown`; `i_fps_num`/`i_fps_den`; `i_timebase_num`/`i_timebase_den`; `b_tff`; `b_pic_struct`; `b_fake_interlaced`; `b_stitchable`; `b_opencl`; `i_opencl_device`; `opencl_device_id`; `psz_clbin_file`.

**Slicing and callbacks**

`i_slice_max_size` (bytes including estimated NAL overhead), `i_slice_max_mbs`, `i_slice_min_mbs`, `i_slice_count` (rectangular slices), `i_slice_count_max`; `param_free` — optional deallocation callback for parameters stored long-term; `nalu_process` — optional low-latency per-NAL callback; `opaque` — internal-use pointer.

### 3.4 Zones and levels

`x264_zone_t` fields: `i_start`, `i_end` (frame-number range), `b_force_qp`, `i_qp`, `f_bitrate_factor`, and a pointer to a per-zone `x264_param_t`. Later zones override earlier overlapping ones.

`x264_level_t` fields: `level_idc`, `mbps`, `frame_size`, `dpb`, `bitrate`, `cpb`, `mv_range`, `mvs_per_2mb`, `slice_rate`, `mincr`, `bipred8x8`, `direct8x8`, `frame_only`. The exported `x264_levels[]` array lists all standard levels and is terminated by an entry with `level_idc == 0`. `x264_chroma_format` is an exported integer: zero means no encoding restriction, otherwise it is the single supported `X264_CSP_*` chroma format.

### 3.5 Parameter functions

| Signature | Contract |
| --- | --- |
| `void x264_param_default(x264_param_t*)` | Fill defaults and perform CPU detection |
| `int x264_param_parse(x264_param_t*, const char *name, const char *value)` | Set one named option. Returns `0` on success or `X264_PARAM_BAD_NAME` (-1), `X264_PARAM_BAD_VALUE` (-2), `X264_PARAM_ALLOC_FAILED` (-3). `NULL` value means "true" for booleans, bad value otherwise. Numeric ranges are checked later at open/reconfig time. May allocate memory that `x264_param_cleanup` frees; a leading `=` in the value is ignored; underscores in names are treated as hyphens; a `no` prefix inverts boolean values |
| `void x264_param_cleanup(x264_param_t*)` | Free library-allocated members without freeing the struct itself |
| `int x264_param_default_preset(x264_param_t*, const char *preset, const char *tune)` | Defaults plus preset and tune; either string may be `NULL`; presets may be given by numeric index `0..9`; multiple tunes separated by `,./-+`, but only one psy tuning; returns negative on invalid names |
| `void x264_param_apply_fastfirstpass(x264_param_t*)` | When first-pass mode is active (`b_stat_write && !b_stat_read`), switch to faster settings |
| `int x264_param_apply_profile(x264_param_t*, const char *profile)` | Only *lower* settings to meet a profile's restrictions; never raises them. `NULL` is a no-op. Returns negative on unknown profile |
| `void x264_nal_encode(x264_t*, uint8_t *dst, x264_nal_t*)` | Serialize a NAL into a caller buffer; required by the `nalu_process` callback contract |

Required call order to emulate the CLI: default/preset, user options, fast-first-pass, profile. The CLI skips fast-first-pass for the `placebo` preset or when `--slow-firstpass` is set.

### 3.6 Picture types and functions

- `enum pic_struct_e`: `AUTO=0`, `PROGRESSIVE=1`, values 4–9 for top/bottom field pairs and triples, `DOUBLE=8`, `TRIPLE=9`. Plain `TOP`/`BOTTOM` values are not supported; x264 uses PAFF only at the frame-pair level.
- `x264_hrd_t`: four doubles — CPB initial arrival, CPB final arrival, CPB removal time, DPB output time; output only when HRD signalling is enabled.
- `x264_sei_payload_t`: `payload_size`, `payload_type`, `payload` pointer; payloads are raw Annex D SEI contents (not NAL-encapsulated), with alignment bits included, written in input order except after a buffering-period SEI when HRD is on.
- `x264_sei_t`: `num_payloads`, `payloads` array, optional `sei_free` callback.
- `x264_image_t`: `i_csp`, `i_plane`, `i_stride[4]`, `plane[4]`.
- `x264_image_properties_t`: per-macroblock arrays in raster order (`quant_offsets` with optional `quant_offsets_free`; `mb_info` with optional `mb_info_free`), plus outputs `f_ssim`, `f_psnr_avg`, `f_psnr[3]`, `f_crf_avg`. `X264_MBINFO_CONSTANT` is bit 0 of `mb_info`; on output the flag is cleared when decoded pixels changed (P-frames only, no false positives but possible false negatives, deblocking ignored). Quant offsets require AQ to be enabled; behaviour is undefined if they differ between passes.
- `x264_picture_t`: `i_type` (force frame type in, actual type out), `i_qpplus1` (force QP in, `X264_QP_AUTO` = auto), `i_pic_struct`, `b_keyframe` (out), `i_pts` (in/out), `i_dts` (out; may be negative initially), `param` (per-frame parameter override taking effect in coded order), `img`, `prop`, `hrd_timing`, `extra_sei`, `opaque`. Forced types that violate encoder settings are corrected with a warning.
- `x264_picture_init(pic)` — initialize a caller-allocated picture.
- `x264_picture_alloc(pic, csp, width, height)` — allocate planes; returns `0` on success, `-1` on allocation failure or invalid colorspace.
- `x264_picture_clean(pic)` — free a picture allocated by `x264_picture_alloc` only.

### 3.7 Encoder functions

| Signature | Contract |
| --- | --- |
| `x264_t *x264_encoder_open(x264_param_t*)` | Create an encoder; all parameters are copied. The public name is macro-glued to `x264_encoder_open_<X264_BUILD>` for ABI enforcement |
| `int x264_encoder_reconfig(x264_t*, x264_param_t*)` | Apply a subset of parameters immediately (to a later coded frame, not necessarily the next input frame); returns negative on validation error. Not all fields are mutable; switching away from ultrafast is especially incomplete |
| `void x264_encoder_parameters(x264_t*, x264_param_t*)` | Copy current internal parameters out; pointed-to strings must not be modified |
| `int x264_encoder_headers(x264_t*, x264_nal_t**, int*)` | Return SPS/PPS NALs and total byte count; payloads contiguous; negative on error |
| `int x264_encoder_encode(x264_t*, x264_nal_t**, int*, x264_picture_t*, x264_picture_t*)` | Encode one picture. `pic_in` may be `NULL` to flush. Returns byte count, zero when no NALs, negative on error |
| `void x264_encoder_close(x264_t*)` | Destroy the encoder |
| `int x264_encoder_delayed_frames(x264_t*)` | Number of buffered frames still to be flushed |
| `int x264_encoder_maximum_delayed_frames(x264_t*)` | Upper bound on delayed frames for the current settings |
| `void x264_encoder_intra_refresh(x264_t*)` | Request an intra refresh on the next P-frame (requires `b_intra_refresh`); not during encode; multi-pass calls must match |
| `int x264_encoder_invalidate_reference(x264_t*, int64_t pts)` | Interactive error resilience: forget a frame and all dependents, forcing a keyframe if none remain. Incompatible with B-frames and intra refresh; recommends large `i_dpb_size` and keyint; may be called concurrently, not during encode; returns negative on failure |

### 3.8 The `nalu_process` callback contract

When `nalu_process` is set, it is invoked for each finished NAL before the frame completes, enabling low-latency transmission. The callback must (1) provide an output buffer of at least `nal->i_payload*3/2 + 5 + 64` bytes and (2) call `x264_nal_encode` into it. The callback must be re-entrant; data stays valid until the next `x264_encoder_encode`. It does not work with frame-based threading (disable threads or enable sliced threads), buffering-period SEI is not delivered through it, NAL order is unspecified under sliced threading (use `i_first_mb`/`i_last_mb`), and `x264_encoder_encode` then returns no valid NALs.

## 4. State and data structures

Ownership rules are central:

- The library owns `x264_t` and everything reachable from it; applications only hold the opaque pointer.
- `x264_param_t` is caller-owned plain data. Library-allocated members created by `x264_param_parse` must be released with `x264_param_cleanup`; parameters embedded in pictures or zones need the optional `param_free` callback because their lifetime is indefinite.
- `x264_picture_t` planes are caller-owned unless allocated via `x264_picture_alloc`, in which case only `x264_picture_clean` may free them.
- NAL arrays and payloads are library-owned scratch memory, valid only until the next encode/headers call.
- `extra_sei` payloads and `quant_offsets`/`mb_info` are caller-owned; optional free callbacks let the library release them after use.
- `x264_levels[]`, `x264_chroma_format`, `x264_preset_names`, `x264_tune_names`, `x264_profile_names` and the various name tables are immutable exported globals.

Invariants assumed by the API: width/height must be set before open; `i_fps_num`/`i_fps_den` or a VFR timebase must be valid; SAR components must be positive and coprime; `i_csp` must be a supported chroma format for the build; forced picture types must not contradict stream parameters; macroblock-indexed arrays must have one entry per padded macroblock (padding to 16, or 32 in interlaced mode).

## 5. Algorithm / behaviour

Contracts and ordering rules not already captured in section 3:

- **Parameter lifetime across frames.** A `param` pointer attached to an input picture takes effect from that frame forward in *coded* order. Some settings (aspect ratio) can only change at an IDR/GOP boundary; callers must force an IDR for immediate effect.
- **PTS/DTS.** VFR input uses timestamps plus timebase for rate control; CFR input uses frame rate only. Muxers must handle initially negative DTS. Pulldown requires constant timebase equal to the output frame rate, PTS after pulldown, and frame doubling/tripling requires `b_vfr_input == 0`; the caller is responsible for managing pic_struct changes.
- **Profile application is monotonic downward.** Applying High to Baseline-compatible settings leaves the stream Baseline.
- **Preset numeric indices.** `x264_param_default_preset(..., "3", ...)` is accepted, mapping from `0 = ultrafast` through `9 = placebo`; the mapping is ordinal and may shift if presets are inserted.
- **Fast first pass.** Only active when writing stats without reading them; it reduces refs to 1, disables 8x8 DCT and all inter partitions except those already set, selects diamond ME, caps subme at 2, disables trellis and re-enables fast P-skip.
- **Reconstruction shortcuts.** The encoder may skip deblocking or other reconstruction work on frames not used as references; `b_full_recon` forces complete reconstruction at a small speed cost.
- **Error resilience.** `invalidate_reference` requires large `i_dpb_size` to retain older fallback frames; increasing DPB does not increase ME work, unlike increasing `i_frame_reference`.
- **Threading interactions.** `nalu_process` is incompatible with frame threading; B-frame support is incompatible with reference invalidation; non-deterministic optimizations trade repeatability for slight quality.
- **OpenCL.** Available only for 8-bit builds; `i_opencl_device` is a CLI ordinal, while API users pass an explicit `cl_device_id` through `opencl_device_id`.

Representative library defaults (declared here, implemented in `common/base.c`): CRF 23, preset medium, 3 reference frames, keyint 250, 3 B-frames with fast adaptive decision, normal B-pyramid, CABAC on, deblocking on at 0:0, hex ME with range 16, subme 7, trellis 1, AQ variance mode strength 1.0, lookahead 40, MB-tree on, 25 fps, I420, VFR input on (CLI overrides to CFR in several paths), annex-B and repeated headers on, log level info.

## 8. Performance notes

The header itself has no runtime cost, but it exposes the controls that dominate encoder speed:

- Preset choice is the primary lever: the ordinal scale spans roughly two orders of magnitude in speed. `--preset` maps to a small set of field changes; the CLI help text enumerates them.
- Hot knobs by phase: lookahead (`rc.i_lookahead`, `i_sync_lookahead`, `i_lookahead_threads`), frame analysis (`analyse.i_me_method`, `i_me_range`, `i_subpel_refine`, `i_frame_reference`, `analyse.inter`, `i_trellis`, `i_direct_mv_pred`), threading (`i_threads`, `b_sliced_threads`, `b_deterministic`), and rate control (`b_mb_tree`, `i_aq_mode`).
- `b_full_recon` and `psz_dump_yuv` add reconstruction work; `b_psnr`/`b_ssim` add per-frame metric computation.
- `b_cpu_independent` and `b_deterministic` can cost speed but guarantee reproducibility across machines/runs.
- `nalu_process` with sliced threads reduces end-to-end latency; frame threading increases throughput but increases delay.
- CPU flags determine which hand-written kernels run; forcing a subset via `--asm` can be used to measure kernel contributions.
- Public references: x264 preset/tune documentation on the project wiki, `doc/threads.txt` and `doc/ratecontrol.txt` in the reference tree, and H.264 Annex A for level-derived MV/DPB limits.

- Verify `X264_BUILD == 164` and that linking against a library with a different build number fails at link time (symbol `x264_encoder_open_<build>`).
- Verify all listed constant values and name-table spellings by compiling assertions against them.
- Call `x264_param_default` and check representative defaults: CRF 23, ref 3, keyint 250, bframes 3, subme 7, me hex, trellis 1, fps 25/1, annexb 1, repeat headers 1, log level info.
- Call `x264_param_default_preset` with numeric `"0"` and confirm it equals `"ultrafast"`; with `"9"` equals `"placebo"`; with an unknown name it returns negative.
- Confirm `x264_param_parse` maps a leading `no` to false, treats `NULL` as true for booleans, tolerates underscores in names and a leading `=` in values, and returns `X264_PARAM_BAD_NAME`/`BAD_VALUE` appropriately.
- Confirm `x264_param_apply_profile` on a baseline-compatible configuration does not add features, and returns negative for an unknown profile.
- Verify `x264_picture_alloc`/`x264_picture_clean` round-trip with plane strides for 8- and 10-bit I420.
- Verify that after `x264_encoder_encode` returns, NAL payload bytes match a reference decode, and that a subsequent encode invalidates the previous pointer (do not dereference it).
- Verify `x264_encoder_delayed_frames` reaches zero after flushing with `NULL` input.
- Verify the `nalu_process` buffer-size contract by enabling the callback with sliced threads and confirming every NAL is delivered before the corresponding frame finishes.
